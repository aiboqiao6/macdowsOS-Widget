# 2026-09-21 稳定性检查

检查覆盖应用入口、桌面窗口管理、实时背景捕获、OpenGL 渲染、组件库、组件设置与网络请求，以及现有回归测试。在原有未提交修改上继续修复，未回退已有功能。

## 已修复

- 实时模式下，静止卡片也持续按显示器刷新间隔渲染；拖动结束不会关闭实时渲染。隐藏、完全遮挡和用户选择的节能模式仍限制刷新。
- 移除根据颜色判定错误帧的逻辑，真实的纯黑、纯白内容可以正常更新，不会被旧图片替换。
- Windows 捕获回调改为持有独立共享状态，避免异步回调访问已销毁对象。帧在最后一个使用者释放后关闭；捕获初始化失败也完整清理资源。
- 根据捕获帧的实际尺寸重建缓冲池，重建时释放回调锁，避免窗口缩放时的锁等待。捕获线程的 WinRT 初始化和反初始化配对，并保证先销毁捕获流。
- 不再调用可能同步阻塞的 `PrintWindow`。销毁最后一个组件时异步回收捕获流，保留已排队请求的完成通知。
- 修改设置和 DPI 时仍保持单个组件最多一个后台捕获请求，避免旧请求清除新请求的占用状态。闲置捕获流回收，超过缓存上限时仅淘汰最久未使用的流。
- 使用 `EnumWindows` 遍历动态窗口列表，恢复其他应用窗口时使用异步窗口定位。
- 修复城市搜索关闭时 `abort()` 同步触发回调、清空指针后再次访问的崩溃风险，并为搜索设置超时。
- 避免尝试从空路径加载背景图。新增可独立构建的测试工程，隔离每项测试的持久化设置。

捕获回调的生命周期处理参考了 Microsoft 对[异步事件撤销与对象生命周期](https://learn.microsoft.com/en-us/windows/apps/develop/cpp-winrt/handle-events#revoke-a-registered-delegate)的说明：撤销事件不保证已在途的回调不会继续到达。

## 验证范围与限制

验证环境：Windows 11、Qt 6.11.1、MSVC v143、Release x64。测试包含静止刷新、黑白背景切换、重复缩放与销毁、不同组件叠放、前景遮挡、截图模式、组件库动画、设置恢复、CPU/GPU 渲染以及网络取消。

- Release x64 构建成功，`git diff --check` 通过。
- 最终产品代码的完整回归：58 项通过，0 失败，0 跳过，约 66 秒。
- 随后新增的静止动态背景帧率测试单独通过：2 秒内接收 52 次背景变化，测试源产生 97 帧。实际捕获吞吐受系统合成和 GPU 回读影响，持续刷新不等于保证每帧都与显示器同步。
- 120 秒连续动态背景与缩放测试通过；加上销毁重建、网络取消验证共约 130 秒。预热后的私有内存 219,787,264→195,170,304 字节，进程句柄 563→564，GDI 对象 18→18。期间未出现崩溃、无响应或持续资源增长。
- 日志：`obj/regression/final-full.txt`、`obj/regression/cadence.txt`、`obj/regression/stress.txt`。可执行文件：`x64/Release/macdowsOSWidget.exe`。
- 部署工具仍提示未设置 `VCINSTALLDIR` 和未定位 D3D12 编译器；编译与链接成功，输出目录已有 VC 运行库和相关 DLL。本项目渲染使用 OpenGL，捕获使用 D3D11。

当前未提供原始崩溃转储，因此不能把某一个风险点认定为历史崩溃的唯一原因。短时压力测试也不能证明数小时运行、休眠唤醒、显卡驱动重置或多显示器热插拔一定无问题。复测命令见 [README.md](README.md)。
